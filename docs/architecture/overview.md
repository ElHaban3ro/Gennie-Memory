# Arquitectura vigente

Esta base prepara un experimento local de recuperación, no el producto completo descrito en `README.md`. El proceso `iromem` carga configuración, abre una conexión SQLite, valida el registro de módulos y aplica migraciones. Su CLI puede cargar revisiones sintéticas y vectores versionados, buscar candidatos FTS5 o por coseno exacto + RRF con ámbito, entidad opcional, revisión y vigencia filtrados. La respuesta FTS5 indica `semantic_coverage: disabled`; la híbrida informa cobertura y degradación. Ninguna búsqueda por sí sola es una semilla clasificada. `recall` añade un recorrido textual integrado: búsqueda, Decisions o Jev por OpenRouter y composición validada.

`SearchRequest` usa `query_mode: "keywords"` por defecto cuando se omite el campo. `apps/retrieval` prepara la consulta FTS5 a partir de la pregunta, sin modificar índices ni recuerdos; `bootstrap` conserva el mismo transporte JSON. La ruta híbrida natural sigue disponible mediante `hybrid-search` y como referencia de cobertura, ya que la ruta rápida pierde algunos positivos en la comparación sintética. [Medición](../evaluation/keyword-preflight-v1.md). El comando `recall` integra la selección tipada en Rust para esta ruta textual.

`kernel` contiene infraestructura y contratos sin negocio. `apps/retrieval` posee las tablas, el índice FTS y el flujo de búsqueda. `bootstrap` es el único punto de composición. No hay `contracts` porque no hay ciclo de apps. El grafo es `bootstrap → retrieval → kernel`, y `bootstrap → kernel`. Una sola conexión pasa desde bootstrap a cada operación; no existe pool. `session` mantiene un proceso CLI local mientras recibe líneas JSONL por stdin y termina al cerrar la entrada; `op: recall` reutiliza el cliente OpenRouter y la conexión SQLite. No abre un servicio de red.

Los límites del MVP están en [ROADMAP.md](../../ROADMAP.md): el índice versionado, el filtro de entidad opcional y RRF sirven pilotos, pero faltan resolver identidad real, perfil de embedding independiente, fragmentos, fuentes verificadas y entrega automática de la semilla a Codex. El [esquema v1 de referencia](../../outputs/iromem/schema-v1.sql) describe un producto más amplio; las migraciones actuales son menores.
El [banco sintético](../evaluation/contract-v1.md) conserva FTS5, híbrido y resultados históricos de Laya. La evaluación vigente está en `tools/evaluation/`: un binario Rust ejecuta búsqueda, campañas Decisions/Jev, comparación Engram y turnos aislados de Codex; también valida bancos y renderiza figuras. La [corrida final](../evaluation/rust-migration-v1.md) mide el nuevo `recall` en 540 preguntas reservadas. No hay codificador Laya activo; el híbrido Rust acepta vectores precalculados.
La [evaluación v2](../evaluation/general-memory-v2-results.md) descartó Laya como clasificador. Decisions y Jev son los clasificadores vigentes; la cascada Decisions → Jev se descartó tras medir un falso recuerdo y más latencia. Los [perfiles v1/v2](../../config/classifier-profile-v2.json) documentan campañas históricas, pero no los lee el producto. La CLI Rust `recall` selecciona proveedor y búsqueda por solicitud; el adaptador HTTP vive en bootstrap y el servicio de recuperación valida la elección. [Contrato](../evaluation/contract-v1.md).
La CLI `compose-seed` y su variante por lotes toman una selección externa, revalidan ID y revisión frente a candidatos FTS5 o híbridos del ámbito solicitado y componen síntesis persistidas con condición y fuente declarada cuando el fixture las contiene. `recall` produce esa selección mediante OpenRouter en el mismo proceso Rust y conserva la revalidación tras la llamada remota. Ante fallo devuelve candidatos sin semilla fiable. Faltan verificación de fuente, aplicabilidad semántica integrada y presupuesto completo de semilla.

Antes de añadir una app o cruzar áreas, lee `AGENTS.md`, las reglas enrutadas y [modules.md](modules.md). La semilla final debe preservar fuente, estado, revisión y condiciones; el clasificador no puede inventar contenido ni sustituir el filtro estructurado.
