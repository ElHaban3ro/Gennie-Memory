# Configuración y secretos

Propietarios: `kernel/src/config.rs`, `bootstrap/src/main.rs`, `.env.example` y `.env` local ignorado. Hoy la única variable obligatoria es `IROMEM_DATABASE_PATH`; no hay default implícito en código. El `.env` local fija `.local/iromem.db` para desarrollo, fuera de Git. Las variables ya exportadas tienen precedencia sobre `.env`. La app puede arrancar con solo entorno, sin archivo.

`Config` contiene la ruta no secreta; `Secrets`, sin `Debug`, lee opcionalmente `IROMEM_OPENROUTER_API_KEY`. No almacenes tokens en `Config`, en `AppState`, logs, errores, fixtures o `.creation/`. La variable está comentada en `.env.example` sin valor real. El adaptador Rust de OpenRouter sirve `recall` y `session`; `iromem-eval` invoca esa misma ruta para campañas sintéticas. Para proveedores nuevos, usa nombres `IROMEM_*`; documenta los placeholders sin credenciales. Valida ausencia, vacío, rango y combinación antes de abrir recursos; no elijas una base distinta al faltar la ruta. Las variables ya exportadas prevalecen sobre `.env`; si incorporas un aviso de discrepancia, informa solo el nombre, nunca el valor.

Los [perfiles de campaña v1 y v2](../../config/classifier-profile-v2.json) se conservan como metadatos de resultados históricos; el runner Python que los leía fue retirado. La CLI Rust `recall` fija la política vigente mediante sus valores por defecto y los campos de cada consulta: `provider` opcional elige Decisions o Jev y `search.query_mode` elige el modo FTS5. El evaluador Rust invoca la misma CLI, sin leer esos perfiles. `IROMEM_OPENROUTER_API_KEY` se lee del entorno o `.env` al invocar `recall`, nunca de su JSON; una búsqueda vacía no requiere petición remota. El perfil definitivo de embeddings y la configuración editable del producto siguen pendientes: al incorporarlos, fija identidad, revisión, archivos/tokenizer, límites y compatibilidad de espacio; distingue configuración de proceso de ajustes editables por app. Toda notificación de cambios persistidos se envía después del commit. Una nueva variable exige actualizar lector, ejemplo, docs y una prueba de configuración en el mismo cambio.

Comprobación actual: `IROMEM_DATABASE_PATH=/ruta/temporal.db cargo run --offline -p iromem -- init-db`. Usa una ruta de prueba, no la base del usuario. El error por variable faltante se comprueba con entorno controlado; no borres `.env` ajeno para hacerlo.
