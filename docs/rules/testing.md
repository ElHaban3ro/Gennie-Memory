# Verificación proporcional

Propietarios: pruebas junto a `apps/retrieval/src/`, fixtures sintéticos en `tests/fixtures/`, comandos Cargo desde la raíz. Los ejemplos sintéticos no contienen recuerdos reales. La suite actual verifica ámbito, revisión, entrada FTS, vectores/cobertura y rechazo de elecciones no presentadas al clasificador. Los pilotos acotados verifican clasificación integrada con FTS5 o híbrido y semilla, sin probar el conjunto completo de métodos, permisos de un host, latencia del hook ni despliegue.

Para cambios de búsqueda o SQL: `cargo test --offline -p iromem-retrieval`. Para cambios de contratos, kernel, migraciones, registro o Cargo: `cargo test --offline --workspace`. Antes de entregar: `cargo fmt --all --check`. Una comprobación CLI breve usa una DB temporal: carga `tests/fixtures/small-corpus.json` y consulta `tests/fixtures/small-query.json` con `IROMEM_DATABASE_PATH` apuntando a esa DB; limpia solo los archivos que creó la prueba. `recall` se verifica con proveedor falso para éxito, abstención y fallo; una llamada real sintética es una comprobación aparte y se declara explícitamente. No ejecutes dos Cargo a la vez sobre el mismo target.

Las pruebas significativas cubren comportamiento observable y fallos, no repiten simplemente la implementación. Al añadir proveedores, separa unitarias deterministas, integración local de Laya y llamadas remotas. El benchmark grande requiere definir corpus y duración prevista, además de presupuesto o autorización expresa para ejecutarlo sin tope monetario; no lo añadas a hooks ni CI obligatoria. La autorización vigente para esta investigación sintética permite ejecutarla sin tope monetario y exige registrar el coste informado o reservado. Registra qué se probó en el código actual y qué solo se revisó estáticamente. Una prueba pasada en un commit anterior o el verificador SQL adjunto al README no prueba la implementación presente.

`iromem-eval retrieval` valida etiquetas y resume búsqueda desde JSONL congelado sin base de datos. `search-benchmark`, `campaign`, `campaign-report`, `engram-benchmark`, `codex-prompt`, `codex-engram`, `paired-flow-report`, `render-charts` y `render-keyword-charts` ejecutan las mediciones actuales en Rust. Los diarios de proveedor se sincronizan antes y después de cada llamada y no se reintenta una petición incierta automáticamente. La comparación con el evaluador histórico sobre 1.600 casos coincidió dentro del redondeo.

Banco actual: `iromem-eval validate-benchmark tests/benchmark/v1` y el mismo comando con `v2`–`v5` comprueban las cinco suites versionadas; `validate-general-memory tests/fixtures/general-memory-v1` y `validate-candidate-matrix tests/benchmark/candidate-matrix-v1/{100,200,2000}` comprueban los bancos adicionales. `search-batch` permite una corrida CLI con conexión compartida y DB temporal. `cargo test --offline -p iromem-retrieval` cubre ámbito, revisión, vectores, cobertura parcial, condiciones, fuente y candidatos presentados. Las pruebas Python antiguas fueron retiradas; los resultados históricos siguen congelados. La comparación actual está en [rust-migration-v1.md](../evaluation/rust-migration-v1.md). No ejecutes la partición final al ajustar instrucciones o umbrales; una muestra de desarrollo no establece superioridad de modelo.

El [seguimiento v2](../evaluation/general-memory-v2-results.md) usó sujetos 006–009; la [expansión léxica](../evaluation/keyword-prefix-v1.md) consumió 010–013 como cohorte nueva después de fijar el cambio. No reutilices ninguno para ajustar prompts o umbrales y conserva sujetos posteriores al 013 para validación futura. Las campañas nuevas solo clasifican con Decisions y Jev; Laya aparece únicamente en vectores y resultados históricos.

La [comparación de la consulta rápida](../evaluation/keyword-preflight-v1.md) mide el binario anterior y el nuevo con la misma base y las preguntas generales ya congeladas. `query_mode: "keywords"` es ahora el predeterminado en `search`; la ruta híbrida natural sigue disponible explícitamente. No se promueve un salto semántico automático basado solo en lista vacía: esa regla no recuperó los casos omitidos. La prueba de seis casos con Decisions y la simulación de Codex tienen alcances distintos y se informan por separado. Un cambio de predeterminado se comprueba con una prueba focal de contrato, sin repetir campañas remotas históricas.
