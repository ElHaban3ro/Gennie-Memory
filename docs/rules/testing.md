# Verificación proporcional

## Contrato de producto v1 (2026-10-23)

Al modificar product/segmentation, probar conservación literal UTF-8, ámbitos, aclaración sin llamadas, roles/IDs/revisiones, presupuesto y degradación. Al modificar transporte, probar timeout global, metadatos tipados y error HTTP 200 con mocks propios. El contrato compartido requiere suite offline workspace; validate-product-suite comprueba separación prospectiva y, con corpus, política y evidencia ligadas sin inferencia. audit-product-reviews verifica cobertura y procedencia de dos revisiones separadas; acuerdo no acredita calidad ni resuelve observaciones por sí solo. [Contrato y límites](../architecture/product-contract-v1.md).

Propietarios: pruebas junto a `apps/retrieval/src/`, fixtures sintéticos en `tests/fixtures/`, comandos Cargo desde la raíz. Los ejemplos sintéticos no contienen recuerdos reales. La suite actual verifica ámbito, revisión, entrada FTS, vectores/cobertura y rechazo de elecciones no presentadas al clasificador. Los pilotos acotados verifican clasificación integrada con FTS5 o híbrido y semilla, sin probar el conjunto completo de métodos, permisos de un host, latencia del hook ni despliegue.

El [cierre de M5](../evaluation/m5-closeout-2026-10-17.md) distingue concordancia histórica de IDs y verdad factual. Una selección en un caso etiquetado negativo puede aportar evidencia que refuta la pregunta; no la llames falsedad sin inspeccionar la afirmación producida. Conserva etiquetas y resultados originales cuando una auditoría posterior detecte un problema; usa anotación separada y explícitamente retrospectiva, nunca un porcentaje nuevo presentado como validación. Una próxima rúbrica debe separar apoyo, refutación, contexto parcial e irrelevancia antes de llamar al proveedor. `audit-m5` revalida hashes, eventos, límites estructurados y fidelidad de texto de las campañas congeladas sin red; no verifica fuentes externas ni respuestas finales.

`screen-search-configs` compara seis configuraciones locales de recuperación en tres rondas alternadas, sin proveedor ni reserva. Un recorte que pierda evidencia de refutación o contexto parcial no pasa el filtro aunque conserve los positivos. Los bytes de resúmenes no son tokens ni una medición de ahorro remoto; pasar este filtro solo permite proponer una prueba posterior de selección, no cambiar automáticamente el producto.

La prueba emparejada de presupuesto usa `prepare-config-selection`, `campaign` y `report-config-selection`: compara 20/10 para la misma pregunta con orden alternado. Audita semillas contra corpus con `audit-m5` antes de interpretar las categorías. Una abstención nueva que elimina apoyo, refutación o evidencia parcial seleccionada antes bloquea la candidata; una selección nueva no anotada exige revisión. El experimento sigue siendo desarrollo conocido y no valida verdad de una respuesta final ni rendimiento poblacional.

`validate-evidence-benchmark` comprueba el banco prospectivo de cuatro relaciones (`tests/fixtures/conversation-evidence-v1`): hashes de rúbrica y archivos, citas fuente, ámbitos, IDs y procedencia. `report-evidence-retrieval` verifica las búsquedas congeladas y desglosa cobertura; no mide selección ni verdad. En ese banco, `expected_ids` incluye evidencia de refutación y contexto parcial: el informe debe usar las relaciones explícitas, sin llamarlas respuestas completas o comparar su agregado con negativos vacíos de cohortes anteriores. Una revisión del mismo autor no se presenta como independiente.

Para cambios de búsqueda o SQL: `cargo test --offline -p gennie-memory-retrieval`. Para cambios de contratos, kernel, migraciones, registro o Cargo: `cargo test --offline --workspace`. Antes de entregar: `cargo fmt --all --check`. Una comprobación CLI breve usa una DB temporal: carga `tests/fixtures/small-corpus.json` y consulta `tests/fixtures/small-query.json` con `GENNIE_MEMORY_DATABASE_PATH` apuntando a esa DB; limpia solo los archivos que creó la prueba. `recall` se verifica con proveedor falso para éxito, abstención y fallo; una llamada real sintética es una comprobación aparte y se declara explícitamente. No ejecutes dos Cargo a la vez sobre el mismo target.

Las pruebas significativas cubren comportamiento observable y fallos, no repiten simplemente la implementación. Al añadir proveedores, separa unitarias deterministas, integración local de Laya y llamadas remotas. El benchmark grande requiere definir corpus y duración prevista, además de presupuesto o autorización expresa para ejecutarlo sin tope monetario; no lo añadas a hooks ni CI obligatoria. La autorización vigente permite las pruebas sintéticas de Decisions, Jev y otros modelos de clasificación y sus comparativas, registrando coste y presupuesto disponible antes de pagar. Las consultas a LLM potentes/de frontera se realizan mediante subagentes Codex; la autorización anterior no permite volver a esos modelos por OpenRouter. El coste y la latencia de subagentes no se equiparan a producción ni se declaran gratuitos cuando no hay recibos. Registra qué se probó en el código actual y qué solo se revisó estáticamente. Una prueba pasada en un commit anterior o el verificador SQL adjunto al README no prueba la implementación presente.

`gennie-memory-eval retrieval` valida etiquetas y resume búsqueda desde JSONL congelado sin base de datos. `search-benchmark`, `campaign`, `campaign-report`, `engram-benchmark`, `codex-prompt`, `codex-engram`, `paired-flow-report`, `render-charts`, `render-keyword-charts`, `render-current-charts`, `render-codex-current` y `render-full-comparison` ejecutan las mediciones y figuras en Rust. Los diarios de proveedor se sincronizan antes y después de cada llamada y no se reintenta una petición incierta automáticamente. La comparación con el evaluador histórico sobre 1.600 casos coincidió dentro del redondeo.

Cuando una nueva corrida de rendimiento cambie los resultados vigentes, regenera y revisa **todas** las gráficas de rendimiento actuales del README, no solo la gráfica de la etapa probada. Conserva el estilo editorial Distill ya establecido en las SVG: fondo crema, titulares Georgia, paleta sobria, ejes desde cero, cifras directas y notas de interpretación. Conserva también cada tipo de figura que ya se mostraba: si la cohorte cambia, presenta su versión actualizada en el README y deja la anterior en el informe histórico. Una figura nueva se añade a las existentes; no sustituye silenciosamente las comparaciones de aciertos, latencia, p95 por corrida, preparación de semilla, recorrido completo o Codex con tokens de entrada. Actualiza las cifras y el texto que las acompañan, usando datos medidos e identificando la versión y la cohorte de cada comparación. Si falta una medición para renovar alguna gráfica, complétala antes de presentar el conjunto como vigente o indica explícitamente que esa figura conserva datos anteriores.
