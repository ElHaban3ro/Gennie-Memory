# Clasificador local de relevancia: preflight V1

Fecha:2026-10-22. Hipótesis: un modelo pequeño entrenado para puntuar pares pregunta/documento, ejecutado sin generación y sin proveedor remoto, puede seleccionar evidencia útil preservando fuentes completas. Elimina la dependencia del pool compartido que produjo el429actual. Eso no predice mejor semántica por sí solo; relevancia temática puede confundir refutación, partes, límites y atributos asociados. No reabre ni cambia los experimentos fallidos.

Modelo: Qwen/Qwen3-Reranker-0.6B, revisión exacta `e61197ed45024b0ed8a2d74b80b4d909f1255473`, Apache2.0. Es decoder Qwen3, no encoderBERT. Pesos safetensors oficiales1191588280bytes, SHA256 `27cd75a405b9c1b46b59abfd88aaa209e6fed2a1972cde9b70e7659537c5e65b`. No ejecutar código remoto ni pickle. Archivos/versiones/metadatos y hashes quedan registrados. Descarga ≈1,21GB de assets más dependencias, fuera de Git en caché compartida; entorno uv aislado solo de evaluación. No servidor, API de inferencia, nueva política de producto o integración Rust en esta fase.

Runtime fijado antes de scores: Python3.13, torch2.14.1, transformers5.20.2, safetensors0.8.0, versiones publicadas comprobadas en PyPI. Resolver y archivar dependencias completas antes de inferir; comprobación de avisos limitada a bases consultadas, no garantía exhaustiva. CPU y MPS se comprueban realmente; elegir MPS si disponible y cargar float32 para evitar variación por cuantización. Si no funciona ese backend, registrar fallo de viabilidad y no cambiar versiones/dtype/arquitectura para rescatar el mismo intento. No comparar latencias mezclando CPU/MPS. Sin installs globales; medir carga fría y memoria separadas, sin esconder costes iniciales.

La puntuación sigue la ficha oficial: prefix chat con instrucción de decidir yes/no, campos Instruct/Query/Document, suffix assistant con think vacío; usar exclusivamente logits del último token sobre tokens `yes` y `no`, softmax de esos dos logits. No generar texto o razonamiento. Padding a la izquierda, máscara íntegra; logits_to_keep=1 si la API lo soporta explícitamente. No calibrar o llamar probabilidad de utilidad al score.

Instrucción única congelada, sin ejemplos, etiquetas, IDs de benchmark o resultados:

> Determine whether the document contains evidence that answers the query, explicitly contradicts a premise of the query, or provides a concrete requested partial fact, condition, limit, or measurement status. An explicit contrast about the same requested attribute is useful when it states the queried case has an alternative value and locates the assumed value, configuration, or condition in a different context; this contrast is useful even without the requested answer value, does not assert exclusivity, and does not become a refutation without incompatibility. Mere topical similarity, a fact solely about another entity, or an associated but unrequested attribute is not useful evidence. Preserve negation, modality and scope; silence does not negate a premise.

Umbral único **score≥0,5**, anterior a scores. `useful` agrupa apoyo/refutación/parcial solo para selección; no atribuye un rol aprendido ni una respuesta completa. No convertir B/C en A ni reportar64rolescorrectos. Interpretación fuente íntegra, composición final conserva texto original, ID/revisión; ninguna paráfrasis o reparación manual. Tokenizar sin truncamiento, añadir prefix/suffix íntegros; cota32768porpar. Si excede, registrar operación no soportada, no truncar ni excluir del denominador.

Toda pérdida útil/extra, fallo, cota o score no finito falla la candidata. No cambiar instrucción/umbral ni repetir para seleccionar mejor resultado. Completar el banco ante errores semánticos mientras runtime/recursos permitan; si falla técnicamente, detener y preservar intento.
