# Vías de evidencia con contexto incorporado v1

Protocolo previo a llamadas. La versión de tres factores eliminó un ID ajeno y perdió dos útiles porque contexto=false vetó una corrección y una parte reconocidas. Su ablación posterior solo justificó investigar otra versión; no fue validación ni ahorro. Esta variante explícita `per_memory_scoped_v1` pide dos choices por cada top8recuerdo: dato solicitado para el mismo referente/contexto, y corrección explícita para ese mismo referente/contexto. Un HTTP con16preguntas y recibo único. Jev1.13, keywords/20, fuentes/gold/políticas anteriores y default conservados.

Cada vía exige conjuntamente referente, calificadores de identidad especificados y su evidencia. Los atributos desconocidos preguntados no son calificadores de identidad; una premisa corregida no es otro referente. Dato: un valor, estado explícito o parte concreta solicitada, aunque falten otras partes. Corrección: una cláusula explícita incompatible con premisa exacta. Preparación, otro atributo o requisito asociado y silencio no bastan. No se toman hechos de otros recuerdos.

Composición local: dato_con_mismo_contexto OR corrección_con_mismo_contexto. El contexto no se omite: se evalúa en cada vía. No hay un tercer juicio separado ni se fija identidad=true. La traza `per_memory.scoped_checks` contiene ID/revisión, `requested_fact_same_context` y `premise_correction_same_context`. Estos booleanos son juicios fallables del mismo modelo, no garantía semántica. Retrieval revalida toda la composición; bootstrap construye payload e interpreta respuestas, evaluación verifica JSON aparte. Omisiones o claves inválidas fallan atómicamente, conservando consumo conocido. No hay dependencias, SQL, secretos, puertos ni estado persistido nuevos.

Piloto conocido fijado: las mismas diez preguntasV5 de los pilotos anteriores,20operaciones alternadas contra `per_memory_binary_v5`, ambas Jev1.13. IDs/orden en policy_probe.rs. Primer par2operaciones verifica formato; si completa,18restantes en mismo diario/binario, sin repetir. DB temporal propia, CLI sin puerto,60s previstos, máximo20HTTP, estimaciónUSD0,0025. Congelar corpus/fuente/gold/casos/protocolo/binarios antes de llamar. Recibos reales y errores desconocidos registrados; no reintentar peticiones inciertas ni retirar contexto discutido del gold.

Abrir campaña completa solo si cero ID ajeno, pérdida de evidencia útil del control o degradación, y una ganancia útil o selección no permitida eliminada. Recibos completos, coste/p50/p95<=1,5× control. No compensar pérdidas con ganancias. Reporte Rust exige candidatos iguales por par y trazas/políticas/fuentes/binario/base vinculados. Un piloto no aprueba adopción ni generalización.

Si pasa, sin cambiar prompt/modelo/límites: comparación completa emparejada V5contra Decisions/baseline(64preguntas/128operaciones), y luego V4/V2 conocidas. Misma puerta completa ya vigente: cero selección ajena, pérdida de evidencia/partes disponibles o degradación nueva; alguna mejora, recibos completos y coste/p50/p95<=1,5×. Un fallo detiene esa expansión y se preserva. Solo tras desarrollo aprobado se abre V6 congelada/revisada aparte. No usar V6 para ajustar ni presentar resultados retrospectivos como nuevos. Incorporar únicamente con mejora demostrada y ambas puertas completas.
