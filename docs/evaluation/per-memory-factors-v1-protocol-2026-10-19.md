# Factores independientes por recuerdo v1

Método fijado antes de llamadas. Objetivo: mejorar pertinencia separando identidad, dato solicitado y premisa corregible, sin perder parciales. Variante explícita `per_memory_factors_v1`, Jev1.13, ocho candidatos, una petición con24preguntas `choice` independientes. No son24peticiones. Estado incluye consulta y cada resumen una sola vez, como datos no confiables. No hay ejemplos ni etiquetas del banco en el payload.

Cada recuerdo tiene tres respuestas A/none: `context` acredita mismo referente y calificadores explícitos de identidad; `fact` aporta valor/estado solicitado o parte concreta; `correction` contiene cláusula explícita incompatible con premisa exacta. Corregir una premisa no constituye una identidad distinta. Otro atributo/requisito, silencio, preparación o planificación no bastan para corrección o resultado. Los tres se evalúan independientemente, sin depender de la respuesta de otra pregunta o tomar hechos de otro recuerdo. `none` incluye ausencia o incertidumbre: no demuestra falsedad.

Composición local: `same_context && (requested_fact || premise_correction)`. La traza opcional `per_memory.factor_checks` contiene ID/revisión y tres booleanos por cada candidato del prefijo; no son confidencias ni probabilidades agregadas. Retrieval revalida cardinalidad, IDs, revisión y composición; solo esta política admite la traza. Si falta un factor, hay clave inesperada o respuesta inválida, falla toda la operación sin semilla y conserva recibo global conocido. Bootstrap posee payload/parser; retrieval la regla; evaluación verifica JSON por separado. No hay SQL, recursos, secretos, dependencias o puertos nuevos. Defaults y políticas anteriores conservados.

Piloto conocido: mismas diez preguntasV5 y gold originales del piloto anterior, control `per_memory_binary_v5`, ambos Jev1.13,20operaciones alternadas. IDs y orden quedan fijados en policy_probe.rs. No se usa la conciliación retrospectiva para retirar pérdidas. Congelar fuente/consultas/corpus/manifest/protocolo/casos/binarios antes de red. Primer par2operaciones comprueba formato; si ambas completan, las18restantes usan el mismo diario/binario, sin repetir las primeras. Si falla técnicamente el par, detener y registrar parcial. CLI sin puerto, DB temporal propia. Máximo20HTTP,60s previstos, coste estimadoUSD0,0025; recibos reales mandan, sin reintentos inciertos.

Abrir comparación completa solo con cero ID no permitido, cero pérdida útil del control o degradación y alguna ganancia útil o selección no permitida eliminada. Recibos completos y coste/p50/p95<=1,5× control. No compensar pérdidas con ganancias. El reporte Rust audita pares/candidatos, todas las selecciones y factores, hash de fuente/casos/binario/base y coste conocido/desconocido. Medir qué factor acepta o rechaza los recuerdos problemáticos. No multiplicar el coste global por24ni tratar estos juicios agrupados como observaciones independientes.

Un piloto favorable no aprueba desarrollo ni generalización: después se compara contra Decisions/baseline en el banco completo y cohortes conocidas; solo tras ambas puertas se abre V6 congelada con revisión separada. No ajustar una política usando V6. Si falla este piloto, detener ampliación y conservar la versión. Iteración futura necesita causa explícita y otra versión, no repetir hasta obtener un resultado favorable ni reducir las puertas.
