## Revisión retrospectiva del fallo y alcance de una corrección

El código explica por qué esta falsedad supera V2: `Candidate.revision` es la revisión del registro de memoria seleccionada como `memories.current_revision`; no es la versión del documento fuente ni la vigencia de cada afirmación. `source_ref` y `source_locator` identifican una fuente declarada, pero no expresan versiones ni relaciones de supersesión. Como un mismo resumen puede mencionar el borrador y la versión final, asignar autoridad a todo el recuerdo tampoco resolvería qué cita contesta cada slot.

Añadir `source_status=final` como otro campo producido por el mismo clasificador no sería una comprobación independiente. Una corrección de producto que garantice autoridad por afirmación requeriría procedencia/versionado externo ligado a cada afirmación o cita, su carga y persistencia, y una regla que abstenga si falta o entra en conflicto. Eso cruza contrato, ingestión, base de datos y selección; no se implementa como parche léxico dentro de V2 ni cambia el alcance de los resultados históricos. La matriz queda como control prospectivo para comparar si un clasificador distingue las versiones en los textos disponibles.

El runtime no dispone de un proveedor local de clasificación: los proveedores definidos son Decisions, Jev, Jev 1.14 y Gemma 3 4B a través del adaptador OpenRouter. Por tanto, sin una clave OpenRouter funcional no hay una ruta local equivalente para generar resultados de modelo. La revisión humana ciega de esta matriz no se contabiliza como clasificación automática.
