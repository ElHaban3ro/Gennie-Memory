# 0035 — Esquema compacto de evidencia por slot V2

## Contexto

`slot_evidence_v1` falló 10/10 smokes sintéticos por salida incompatible con las reglas de citas, identidad y roster. TRAIN no se puntuó y la calidad no puede inferirse. La crítica estática observó que el output exigía varios campos redundantes y múltiples citas opcionales expresadas como null.

## Alternativas

- Relajar el binding y aceptar anclas/IDs que aparecen separados en la pregunta.
- Mantener V1 y su coste/errores.
- Crear una política V2 con menos campos remotos, manteniendo las citas contiguas y controles locales.

## Decisión y estado

Se conserva V1 como evidencia negativa y V2 permanece separado y optativo. V2 elimina del output remoto ocurrencia inventada, valor normalizado, predicado, cinco citas contextuales y la cita de ancla generada. Un DTO V2 estricto convierte el wire format a la representación interna: deriva el span literal de identidad en la pregunta a partir de sujeto/tipo/ID con límites y ambigüedad cerrados; permite quitar de `subject` solo tokens completos repetidos del tipo o ID. El tipo se compara ignorando únicamente capitalización ASCII y se conserva con la grafía exacta de la pregunta. Deriva ocurrencia por posición, stable ID desde el ancla validada y dimensión desde la colección (slot o premisa). Conserva cita del sujeto en el resumen, proposición fuente completa, target por relación e igualdad exacta de roster. Los IDs se comparan con límites de token; `supports` y `refutes` pueden conservar evidencia pertinente a premisas. Pruebas locales cubren DTO, spans ambiguos/cruzados, binding adversarial de IDs, este caso de capitalización y preservación de evidencia de premisa. La derivación literal no certifica que el sujeto propuesto por el modelo sea el referente semántico correcto; los falsos referentes deben fallar las puertas de calidad. Siete smokes con recibo fallaron; el octavo terminó en HTTP 429 sin coste conocido y el noveno falló con `slot_evidence_roster_extra`. El subtotal conocido es US$0,00026037; el coste del octavo sigue desconocido. No hay smoke válido ni TRAIN puntuado.

El intento seis completó recibo pero falló con `slot_evidence_v2_kind_not_literal` (US$0,00003248). No se conservó respuesta cruda, así que la diferencia de mayúsculas `employee`/`Employee` solo es hipótesis. La revisión actual tolera únicamente diferencias ASCII de capitalización del tipo: busca el término como token, deriva la forma citada desde la pregunta y valida el resumen con la misma regla. Sujeto e ID permanecen exactos; un ID repetido en la consulta rechaza el ancla por ambigüedad. Las pruebas locales pasan, pero la nueva revisión aún no ha pasado un smoke. TRAIN continúa cerrado.

El intento siete detectó `slot_evidence_v2_kind_absent_from_query` (482/264 tokens; US$0,00003248; 1.845 ms): el tipo propuesto no estaba literalmente en la pregunta, aun tolerando capitalización. No se guardó la respuesta cruda. El prompt ahora prohíbe inferir el tipo desde la memoria y pide omitir el ancla si el query no lo expresa literalmente. No se cambia el validador ni se abre TRAIN; [el protocolo](../evaluation/slot-evidence-v2-protocol-2026-10-23.md) conserva el recibo y la secuencia de intentos.

El intento ocho sobre esa revisión terminó en HTTP 429 sin recibo; coste desconocido. No hay evidencia para distinguir ritmo de peticiones y cuota. Se conserva como fallo técnico y no se reintenta ciegamente. La candidata sigue sin smoke válido; TRAIN está cerrado.

La auditoría local adicional encontró que V2 podía aceptar una atribución falsa incluso si el modelo mentía y ponía `subject_quote=Ana` sobre la cita compuesta `Ana discutió Bob, quien vive en Cusco`. La primera regla que rechazaba todo segundo ID fue descartada tras crítica porque perdía acciones útiles de Ana sobre Bob. La regla actual rechaza una proposición accionable si un ID distinto aparece antes de una relativa, sin confiar en campos adicionales propuestos por el modelo. Para conservar la acción principal, el contrato pide recortar la cita a la cláusula mínima: el banco conserva `Ana aprobó R-5 para Bob (B-29)` aunque la memoria añada `quien vive en Cusco`; también rechaza la cita compuesta parentetizada que atribuye la ciudad de Bob a Ana. La crítica condujo a ampliar el detector a aposiciones de hasta treinta palabras, relativos fuertes sin artículo, complementos wh conocidos y offsets Unicode seguros. El banco sintético r2 conserva las quince trazas y etiquetas anteriores, y añade tres positivos de recuerdos sobre comunicación con otro referente. Tiene 18 trazas (7 útiles aceptadas y 11 inválidas rechazadas); `cargo fmt --all --check` y la suite completa pasan: 953 pruebas correctas, 24 ignoradas y cero fallidas. La crítica independiente confirmó los tres positivos nuevos y preservación de las quince trazas, pero también encontró una ambigüedad conceptual no resuelta: `que estaría` puede ser tanto un complemento útil de una comunicación de Ana como una relativa sobre Bob; una excepción que conserva el primer caso permite atribución falsa en el segundo. `that the…` plantea el mismo tipo de ambigüedad. V2 sigue experimental y no supera aún el gate para smokes comparativos o adopción. El siguiente avance requiere representar o evaluar el rol de la cláusula con contexto, no seguir ampliando listas léxicas sin evidencia.

El proveedor sigue optativo `google/gemma-3-4b-it`; el predeterminado y el baseline del producto no cambian. G0 recibe opciones con letras y G2 el roster con IDs/revisiones, por lo que la comparación evalúa paquetes completos y no mantiene idéntico wire input. La única autorización remota aplica a fixtures sintéticos y recibos/costes informados. [Protocolo V2](../evaluation/slot-evidence-v2-protocol-2026-10-23.md), [smoke V1](../evaluation/slot-evidence-v1-pilot-results-2026-10-23.md).

## Revisión

No ejecutar llamadas V2 puntuables hasta que un crítico independiente apruebe el contrato y tres smokes sintéticos pasen 3/3 con recibo completo y binding correcto. Cualquier falsedad, pérdida o extra en TRAIN rechaza la versión sin abrir particiones reservadas.


El sondeo temporal de parser local no justifica integración: spaCy acertó la relativa española especificativa sin coma, pero clasificó el complemento útil de `dijo` como relativa; UDPipe clasificó correctamente ese complemento, pero adjuntó la relativa sin coma a `habló`. Ambos reconocieron la relativa con coma. Esta divergencia impediría seleccionar con seguridad y muestra que una salida sintáctica única no prueba correferencia. No se añadió dependencia.
