# Plan de inicialización

Estado: inicialización de la base completada; MVP experimental pendiente. Última actualización: 2026-10-15 (America/Bogota).

## Producto y alcance

- Producto: `iROMEM`, interfaz para memorias de agentes de IA en proyectos grandes. Busca recuperar contexto útil con menos tiempo y tokens, mediante recuerdos semilla.
- Público inicial del experimento: el equipo que evalúa la recuperación; Codex será un host posterior, sin hook en el MVP.
- Alcance inicial acordado: experimento local en esta Mac con corpus sintético generado para iROMEM, recuperación estructurada + SQLite FTS5/BM25 + embeddings + RRF + clasificadores Laya, Jev, OpenAI Decisions y modelos por OpenRouter; composición y evaluación de semillas.
- El diseño v0.1 describe un núcleo Rust y superficies MCP/CLI para el producto completo. El MVP solo necesita una interfaz local de ejecución y un banco reproducible; MCP y hook se aplazan. El corpus se cargará por fixtures sin exigir primero todo el contrato de escritura.
- Laya reutilizará la caché ya descargada por SOC en `/Users/fer/Library/Application Support/AIModels`, sin modificarla. Los datos reales pueden enviarse a los proveedores remotos según autorización del usuario, pero las pruebas de este MVP serán sintéticas.
- Fuera del primer hito: hook, integración Codex, API MCP de producto, escritura completa, publicación remota, despliegue productivo y afirmaciones de mejora no medidas.

## Relación con los requisitos

- El prompt completo se conserva en `initialization-prompt.md` y se debe releer junto con `answers.md`, `decisions.md` y este plan antes de generar la base o al retomar la inicialización.
- Las preguntas que alteran la estructura se resolverán antes de crear el workspace. Las decisiones delegadas y supuestos provisionales se distinguirán de los requisitos confirmados.
- La propuesta de módulos, datos, superficies, configuración, construcción y verificación se añadirá cuando existan respuestas suficientes.

## Base local aprobada para esta etapa

- `kernel/`: contratos transversales `AppModule`, configuración de proceso y apertura única de SQLite. Sin dependencia de apps.
- `apps/retrieval/`: memoria semilla sintética, migración inicial, repositorio SQL, búsqueda estructurada/FTS5 y composición básica para una línea base. Sin HTTP, eventos ni tareas de fondo todavía.
- `bootstrap/`: registro explícito, validación de dependencias y CLI `load-fixtures` / `search`. `contracts/` se omite porque no hay un ciclo real entre apps.
- Persistencia: SQLite local en ruta explícita `IROMEM_DATABASE_PATH`; `.env` local no versionado con `.local/iromem.db` como elección provisional para desarrollo. Los casos de prueba usan bases aisladas en memoria.
- Modelo inicial: memoria con ID, ámbito, revisión, tipo, texto original, síntesis, estado y fechas opcionales. El índice FTS5 deriva del contenido confirmado. Los vectores y proveedores se añadirán en los siguientes hitos del roadmap, sin fingir que la línea base textual los implementa.
- Superficie inicial: CLI local, sin hook, servidor HTTP ni MCP. Se reservó el nombre `IROMEM_OPENROUTER_API_KEY` para el futuro adaptador, sin usar todavía su valor.
- Verificación corta: `cargo fmt --check`, `cargo test --workspace` y una consulta CLI con fixtures sintéticos. No se ejecuta la campaña grande.
